# Contributing

Use Node.js 22 or later. Run `npm test` and `npm run check` before opening a pull request. Add a fixture-based test for protocol changes. CI and routine tests must not need credentials or create paid generation requests.

Include observable behavior, the protocol affected, and test results in your pull request. Report model availability using the authenticated catalog, not a copied marketing list. Mark a proposed example as a prompt template until an actual result has been obtained and reviewed.

Keep examples focused on a useful task. Include reference roles and inspection criteria. Do not submit private user media, API keys, signed links, scraped reviews or unsupported quality claims. New capability documentation should link to its relevant maintained API documentation.
